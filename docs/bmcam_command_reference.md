# bmcam command reference (commands v9)

GENERATED by `tools/gen_command_reference.py` from `BM_Devel_Pi/config_registry.py` (registry v8) and `BM_Devel_Pi/command_wire.py`. Do not edit by hand: change the code and regenerate (`--write`); a test fails when this file is stale.

v9 runs on the **supervisor runtime of a migrated (config v2) unit**. The legacy runtime (and the video_logger recorder) still speak the v8 preset verbs until the legacy runtime is deleted after S5 (PLAN_S4.md G1).

## How to send

At the Spotter console (or through the Sofar command API as the same line):

```text
bm pub bmcam/cmd {"id":1000001,"c":"get","k":["mode"]} 1 1
```

- The JSON is at most **248 bytes** including `sig`; the whole console line at most **270 bytes** (the Sofar limit).
- Strict JSON: ASCII only, finite numbers (no NaN), no duplicate keys, `true`/`false` are not numbers, strings `[A-Za-z0-9_:./+-]{1,48}`, lists of 1–4 numbers or names, objects only at the top and as `kv`.
- Every answer is printed on the Spotter console for a person; a cellular ack goes only for the remote and service id ranges.

## Command ids (who sends what)

| range | sender | cellular answer | high-water |
|---|---|---|---|
| 1 – 99,999 | console by hand, dev_mode.sh | no (console) | no |
| 100,000 – 999,999 | backend heals (rsd) | no (console) | no |
| 1,000,000 – 99,999,999 | dashboard, bench GUI, sofar_send_command | yes | yes |
| 100,000,000 – 199,999,999 | signed service commands (bm_service_sign.py) | yes | yes |
| 2,000,000,000 – 4,294,967,295 | bench conductor | no (console) | no |

A re-sent id returns its ORIGINAL answer with `"d":1` (256 kept). In a high-water range an older id is refused `e:"old"`. A service-range id always needs a valid `sig`.

## Verbs

| verb | example | effect |
|---|---|---|
| `ping` | `{"id":N,"c":"ping"}` | liveness |
| `help` | `{"id":N,"c":"help"}` | this summary on the console |
| `get` | `{"id":N,"c":"get","k":["mode","r"]}` | values + source (console; `<CF>` for a cellular id, at most 3 parts); `"k":["journal"]` = the last 5 changes; `"to":"con"` = console only |
| `set` | `{"id":N,"c":"set","kv":{"m":150,"camera.exposure.ev":-1.0}}` | all-or-none, the whole resulting config validated; `"b":"<hash8>"` = compare-and-set |
| `reset` | `{"id":N,"c":"reset","k":["m"]}` / `{"all":1}` | back to the YAML value (a key, short name or group) |
| `cfm` | `{"id":N,"c":"cfm","ref":<set id>}` | confirms a guarded `set` |
| `trg` | `{"id":N,"c":"trg","v":2,"kv":{"d":8}}` | one action now: 0 cancel, 1 capture + save, 2 capture + output per mode, 3 stored reef reference, 4 stored reference card; `kv` = one-shot keys for that action only (never saved) |
| `hld` | `{"id":N,"c":"hld","v":30}` | stay awake v min (0 releases); the ack's `v` is the minutes granted; never saved |
| `rsd` | from the backend heal-commands endpoint | re-send chunks (heals) |
| `wap` | `{"id":N,"c":"wap","v":1}` | 0 boot default, 1 open hotspot 60 min, 2 HQ WiFi 60 min |

Keep-alive: every command received keeps a per_boot unit up `commands.keepalive_s` after it (at most `commands.keepalive_max_s`), within the bus-power budget unless `power.bus_always_on`.

## Answers

- Ack: `{"id":N,"ok":1,"h":"<hash8>"}`; plus `e`/`k` on a rejection, `s:1` staged, `d:1` duplicate, `v` granted hold minutes. `h` = the config fingerprint after the command.
- `<CF v=1 h=<hash8> [n=i/N] key=value[@source] ...>`: `get` answers, the keys a set changed, `reverted=` / `err=` reports. Source `@c<id>` = set by that command, `@v8` = folded from the v8 state, `@d` = registry default, none = the YAML.
- `<WS ... cfg=<hash8> up=<s> ...>` and START `cfg=` carry the hash; a triggered START also `tg=<id>` and the resolved `r=`/`m=`/`d=`.

| e | meaning |
|---|---|
| `id` | id outside every sender range (console answer only) |
| `cmd` | unknown or not-yet-available verb (e.g. a retired v8 verb) |
| `key` | not a setting, not settable this way, or set twice (k = the name) |
| `val` | wrong type, out of range, bad charset, or JSON > 248 B (k = the key); not JSON or no usable id gets NO ack (console line only) |
| `xk` | the resulting config breaks a cross-key or environment rule (k = a key it names) |
| `lock` | a locked key (file paths, commands.runtime, video_logger media): deploy only |
| `auth` | a service key or a service-range id without a valid signature |
| `old` | id at or below this sender range's newest id (send a newer id) |
| `cas` | `b` (compare-and-set) does not match the current config hash |
| `big` | a cellular get needs more than 3 <CF> parts (ask for fewer, or "to":"con") |
| `ref` | cfm of an id that nothing is waiting for |
| `rsd` | every heal of the rsd was refused (<HL> says why) |
| `err` | the state file could not be written: nothing changed (send it again) |

## Guarded keys

- `guarded_revert`: reverts after 2 transmitting actions or 3 boots without `cfm`, and after 2 h of uptime in any case (`mode.output` save_local: 3 boots or 2 h). The revert is reported as `<CF reverted=<key>>`.
- `guarded_stage`: stored, not applied, until `cfm`.
- `locked`: deploy only. `service`: a signed service-range command (`tools/bm_service_sign.py`), then as guarded_revert.
