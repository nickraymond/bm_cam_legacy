## Round 2 — amended items

CONSENSUS ROUND 2 — only the items amended after round 1. Reply AGREE / OBJECT per item, one line each (<= 150 words total). Everything else from round 1 stands, including all additions you each made (they are all adopted; none conflicted).

R3 (K7 safe-minimal; A said halt disabled, B said dry-run): safe-minimal = commands ON, no media action, network.default none, network_type 0x02, power.halt dry_run:true (logged, never executed), stay reachable. Reached only with no last-known-good (fresh unit / corrupt SD). Last-known-good carries power halt, UART, network_type, topic, commands.enabled.

R4 (X1 amended per C): device accepts backend heal ids [1e5, 1e6) and the backend gets a guard refusing allocation >= 1e6 (S6); bench GUI floor moves to 1e6 and sofar_send_command --id is range-checked (S4); heal acks print on the console only (<HL> is the cellular answer); high-water stored per range in state v2, separate from the 256-id result cache; a stale re-send gets e:"old" and the UI re-issues with a new id.

Raw payloads only, <= 1 KB each, 64 entries / 16 KB, drop-oldest, cleared only after state persist; id cache makes crash replay harmless. wap / trg v:0 lose mid-burst immediacy (accepted).

R6 (X4 per C): persisted boot counter incremented before the UART opens; guarded revert after 2 transmitting actions or 3 boots, whichever first; journaled; <CF reverted=> on the next uplink.

R7 (K6 per A): restart wrapper only in stay_on; crash-loop cap 5 in 10 min → fall back to per_boot legacy behaviour; SIGTERM during capture retry waits a bounded time then exits.
