# Pi Zero 2 W Low-Power Mode Test — Results (2026-07-24)

**Board:** Raspberry Pi Zero 2 W Rev 1.0 (`nereus001`, Tailscale 100.97.87.67)
**OS:** Debian 12 Bookworm, kernel 6.12.93+rpt-rpi-v8
**Method:** Runtime-only profiles over SSH ([low_idle.sh](low_idle.sh), [tuned_halt.sh](tuned_halt.sh)); human read an inline USB power meter at each state. No persistent/boot config was changed.

## Results

| State | Duration | Meter reading | Notes |
|---|---|---|---|
| Baseline (untouched, WiFi on, power_save on) | — | **0.600 W** | reading fluctuated (WiFi duty-cycling) |
| low-idle (LED/BT off, governor powersave, WiFi power_save OFF) | 5 min | **0.622 W** | rock-steady, no fluctuation |
| tuned-halt (halted) | until read | **0.260 W** | −57% vs baseline |

**Recovery:** SSH + WiFi + Tailscale re-established on the **first** power cycle, ~35 s boot (SSH answered 11:29:53; halt at 11:25:22, poll included human reading time). Board verified back at stock state after one manual fix (see below).

## Key findings

1. **Halt is the big lever: 0.26 W** — better than the 0.3–0.35 W spec estimate. For long waiting windows, tuned-halt + external power control is the winning strategy.
2. **low-idle drew *more* than baseline (+0.022 W).** Cause: the profile forces WiFi `power_save off` (for SSH responsiveness), which pins the radio awake and outweighs the LED/governor/BT savings. Stock baseline had `power_save on`. The follow-up experiment is low-idle *with* power_save on — likely the real idle savings live there.
3. **rfkill soft-block PERSISTS across reboots** (`systemd-rfkill` restores it at boot). The "reboot = full rollback" assumption is wrong for Bluetooth specifically. Fixed post-test with `sudo rfkill unblock bluetooth`; both scripts now document this.
4. **HDMI-off is a no-op on Bookworm/KMS** (`vcgencmd display_power 0` is ignored; `tvservice` gone). HDMI connector was `disconnected`, so cost ≈ 0 with nothing attached. For boot-level HDMI power-down, use `/boot` config in the future hardening pass (out of scope here).
5. Meter resolution (3 decimals, but single manual readings) is marginal for the baseline-vs-low-idle comparison (Δ22 mW). A logging meter or shunt setup is needed for the power_save sweep.

## Next steps (future sprints, not done here)
